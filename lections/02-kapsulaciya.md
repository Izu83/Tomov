# Капсулация

> Примерна лекция за демото — замени я със записките от часа.

## Идеята

Капсулацията означава да **скрием вътрешното състояние** на обекта и да позволим промяната му само по контролиран начин. Така обектът сам пази данните си валидни.

## Модификатори за достъп

| Модификатор | Клас | Пакет | Наследник | Навсякъде |
|---|:-:|:-:|:-:|:-:|
| `private` | ✓ | | | |
| *(без)* | ✓ | ✓ | | |
| `protected` | ✓ | ✓ | ✓ | |
| `public` | ✓ | ✓ | ✓ | ✓ |

## Getters и setters

```java
public class BankAccount {
    private double balance;

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("Сумата трябва да е положителна");
        }
        balance += amount;
    }
}
```

Отвън никой не може да напише `account.balance = -1000;` — единственият начин да се промени балансът е през `deposit`, който проверява входа.

## Правило за палеца

1. Полетата са `private`.
2. Даваш `get` само ако някой наистина има нужда да чете.
3. Вместо слепи `set`-ове прави методи със смисъл (`deposit`, `withdraw`).
