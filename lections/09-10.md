### Стойности по подразбиране и инициализация

* В C и C++ променливите нямат дефолтни стойности. При липса на инициализация, променливата съдържа така наречената „случайна“ или „боклук“ стойност (*garbage value*), която е останала в съответната клетка на паметта.

> [!NOTE]
> Това важи за **локалните** променливи в C/C++. Глобалните и `static` променливи там се нулират автоматично.


* В Java променливите се инициализират автоматично със стойности по подразбиране:


  * `int` $\rightarrow$ `0`


  * `float` / `double` $\rightarrow$ `0.0`


  * `boolean` $\rightarrow$ `false`


  * `char` $\rightarrow$ празен символ


  * `String` и референтни типове $\rightarrow$ `null`

> [!NOTE]
> Стойност по подразбиране получават само **полетата** на класа и **елементите на масив**. **Локалните** променливи (декларирани вътре в метод) не получават — ако ги използваш, преди да им дадеш стойност, кодът не се компилира. „Празният символ“ при `char` е символът с код 0 — `'\u0000'`.
>
> ```java
> public class Demo {
>     int count;                 // поле → автоматично 0
>     int[] arr = new int[3];    // елементи → {0, 0, 0}
>
>     void test() {
>         int x;                 // локална → няма стойност
>         System.out.println(count);  // 0
>         System.out.println(x);      // ✗ грешка: variable x might not have been initialized
>     }
> }
> ```




* По конвенция в Java примитивните типове се изписват с малка буква (например `int`), докато техните референтни обвиващи класове (wrapper classes) се изписват с главна буква (например `Integer`).

> [!TIP]
> | Примитивен тип | Обвиващ клас |
> |---|---|
> | `int` | `Integer` |
> | `double` | `Double` |
> | `char` | `Character` |
> | `boolean` | `Boolean` |
>
> ```java
> int a = 5;
> Integer b = 5;                    // същото число, но като обект
> Integer c = null;                 // ✓ обектът може да е null
> int d = null;                     // ✗ примитивът не може
> int e = Integer.parseInt("42");   // обвиващият клас има полезни методи
> ```



### Процедурно срещу Обектно-ориентирано програмиране (ООП)

* **Процедурен подход (напр. в C):** Кодът е организиран около независими процедури и функции (действия), които се прилагат върху данни, без тези действия да са обвързани с конкретен обект.


* **Обектно-ориентиран подход (напр. в C++, Java):** Действията (методите) са капсулирани вътре в класовете и принадлежат на конкретни обекти. Класът служи като шаблон (*template*) за създаване на самите обекти.

> [!TIP]
> Една и съща задача — внасяне на пари в сметка:
>
> ```c
> // C — данните и функцията са отделни
> struct Account { double balance; };
>
> void deposit(struct Account *acc, double amount) {
>     acc->balance += amount;
> }
>
> deposit(&myAccount, 100);   // подаваме данните на функцията
> ```
>
> ```java
> // Java — методът принадлежи на обекта
> class Account {
>     double balance;
>
>     void deposit(double amount) {
>         balance += amount;
>     }
> }
>
> myAccount.deposit(100);     // казваме на обекта какво да направи
> ```



### Изкуствен интелект и дисциплина в програмирането

* При използването на генеративен изкуствен интелект (като ChatGPT, Gemini, Claude) за създаване на софтуер, фундаменталните познания и логика остават задължителни. Въпреки че AI може да генерира код и да подпомага разработката, програмистите трябва да имат необходимите знания, за да могат да проверяват, разбират и управляват генерирания резултат.


* Основната разлика между успешните и неуспешните хора в програмирането (както и във всяка друга област) е дисциплината — постоянството да се работи и учи всеки ден.
